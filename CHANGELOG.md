# История версий

## 2.1 — план: персонализация

Всё «про меня» — в одном личном профиле (сделано как `personal/users/<имя>_<фирма>.md`, код `USER`), общие правила ссылаются на него (`ME.LANG.1`), а не
зашивают мои привычки. Каждый пользователь `claude-config` заполняет свой профиль; заполнение — скиллом-анкетой
(`/profile`: вопросы → готовый файл, разумные значения по умолчанию).

Что войдёт в профиль:
- **Язык и формат:** язык общения и артефактов (документы задач, планы), язык коммитов, перевод чужих текстов и его
  формат, краткость ответов, «картинки» вместо текста.
- **Знание технологий:** что знаю хорошо (объяснять кратко), что учу (на шаг глубже, с аналогиями), чего не знаю.
- **Методы объяснения:** прецеденты и код, наглядные примеры, цепочки вызовов — что включать по умолчанию.
- **Работа с тикетом:** нужен ли разбор до «делай», что в нём; оценка — нужна ли, когда (план/факт) и в каком виде;
  что делать после разбора и после сдачи (разбор сделанного, список на коммит, ответ ревьюеру).
- **Разрешения по умолчанию:** читать/писать трекер (Jira), wiki (Confluence), git (commit/push/ветки), PR/MR
  (GitHub/Bitbucket), БД (чтение / запись), логи серверов, установка пакетов; где «только сказать», где «спросить».

Возможно, ещё (дополнить при планировании):
- **Окружение:** ОС (WSL / Windows / macOS), IDE, откуда коммичу (IDE / терминал), терминал и его цвета (URL в блоке).
- **Роль:** бэк / фронт / фуллстек — влияет на `COMM.LEARN` и что проверять самому.
- **Лимит:** сколько можно тратить на фоновые прогоны и субагентов, когда предупреждать.
- **Учёт времени:** нужен ли `/timelog` и его настройки.
- **Память:** что запоминать о пользователе, что — нет.
- **Онбординг:** новый человек — `git clone` → `./install.sh` → `/profile` → готово.

Порядок (15.10.2026): (1) профиль `personal/users/<имя>_<фирма>.md`, код `USER`, активный — симлинк `~/.claude/user.md`
— факты обо мне и окружении; (2) настройки `USER.PREF/WORK/PERM`; (3) правила — ссылками на `USER`, без «я/мне»;
(4) проверка; (5) **инструкция переезда** `skills/rules/v2.0-to-v2.1.md` (как `v1-to-v2.md`) + метка проектов `2.1` —
для ассистента; собрать в конце по `git diff v2.0..v2.1` (что переехало и куда).

Сделано в ветке `v2.1`:
- `WSL.TRAP.4` — Docker из WSL после включения интеграции работает (`docker`, `compose`, Testcontainers), Apply &
  restart останавливает контейнеры; `WSL.TRAP.9` — после обновления WSL (3.0) Docker Desktop не стартует.
- `COMM.EXPL.9` — изменения объяснять «было / стало» на одном примере.
- **Профиль `USER`** — `personal/users/<имя>_<фирма>.md` (первый — `tarlekon_askend.md`), активный — симлинк
  `~/.claude/user.md`, подключён всегда (`RULES.USER.1`). Разделы: `ABOUT` кто я, `PREF` общение, `WORK` как работаю,
  `PERM` разрешения, `SYS` система, `DEV` инструменты, `ACC` доступы (имена), `FOLD` папки, `EVENT` мои события и
  события фирмы, `MORE` по желанию.
- Правила ссылаются на профиль вместо своих фактов о пользователе: `COMM.LANG.1/2/6`, `COMM.BRIEF.1`,
  `COMM.LEARN.1/2`, `COMM.EXPL.9`, `WORK.TICK.1`, `WORK.DISC.4/6`, `WORK.RUN.1`, `WORK.EST.1`, `WORK.DONE.3`,
  `SAFE.OWN.2`, `FILES.NOW.1`, `FILES.WHERE.1`, `WSL.SETUP.1`, `JAVA.SETUP.2`, `NODE.SETUP.2/3`; скиллы `ticket`,
  `commit-message`, `timelog`; шаблон `ticket.md`. Местоимения «я / мне» остаются — это хозяин профиля.
- `RULES.PROJ.6` — раздел проекта `PROJ.EVENT` (стендапы, демо, спринт); у связанных репозиториев — в общем файле
  главного, рядом с `PROJ.TEAM`. Шаблон проекта — с `PROJ.EVENT`.
- `RULES.PROJ.8` — не дублировать: у каждого репозитория группы свой `CLAUDE.md` (тонкий, если своих правил нет) с
  `@`-ссылками на главный; в главном — список, кто подключает; `tech/` главного — только при той же версии.
- `install.sh` — создаёт `~/.claude/user.md`: выбранный оставляет; свой профиль (`<логин>_*`) один — молча; есть только
  чужой — говорит, что он есть, и не берёт; несколько — спрашивает; `--profile <имя>` — сразу. Проверено: новая
  сессия (`claude -p`) видит `USER.*` без чтения файлов.
- `USER.PERM` — только «чьё слово нужно», без пересказа правил (`.4` влился в `.2`, номер пропал — `RULES.CODE.2`);
  `USER.WORK.5` (`/timelog`) помечен «только Askend». README: профиль, «после `git pull` обязательно `./install.sh`».
- «Дерево» с размерами переехало из `home/CLAUDE.md` в `README.md` (`CLAUDE.md` был 12.6 КБ > 12); в `CLAUDE.md` —
  короткий список кодов файлов и утилит (8.2 КБ). `RULES.SIZE.1`, `RULES.NEW.1`, `FILES.TOOLS.4` — по-новому.
- `RULES.USER.1` — в профиль только проверенное (команда, показывающая именно это, или слова пользователя).
- `WORK.DISC.1` — найденное попутно: сказать и спросить, не править (из памяти).
- Память ассистента почищена: факты о пользователе — в `USER`, в `MEMORY.md` — ссылки на номера.
- Переезд: `RULES.MIGR.1` — для любой старой версии; инструкция `skills/rules/v2.0-to-v2.1.md`; с v1 сразу на 2.1 —
  `v1-to-v2.md` → `v2.0-to-v2.1.md` подряд, одна метка в конце. Метка `2.1` — в `home/CLAUDE.md`, шаблоне и пяти
  проектах пользователя.

## 2.0 — 14.10.2026

- Номера правил `ФАЙЛ.РАЗДЕЛ.N` (`COMM.LANG.3`); как читать правила — `RULES` вверху `home/CLAUDE.md` (номера,

- `tech/` вместо `code-rules/`, `gotchas/`, `environment.md`: файл на технологию, разделы `SETUP` / `RULE` / `TRAP`,
  метки версий (`[Jackson 3]`, `[Angular 16+]`).
- `tools/`: `jira.py`, `wiki.py`, `bb-pr.py`, `test-count.sh`, `flyway-checksum.py`.
- Проект: та же раскладка и номера (`.claude/work.md`, `.claude/integ.md`, `.claude/tech/*.md`), «дополняет» /
  «(заменяет)», свои номера от 101, `PROJ.*` в `CLAUDE.md`, метка `<!-- claude-config: 2.0 -->`.
- Документы задач: `<KEY>.md`, `<KEY>.in.*`, `<KEY>.out.*` — без подпапок.
- Скиллы ссылаются на номера, а не повторяют правила.
- Переезд проекта с 1.x — скилл `/rules` (`home/personal/skills/rules/v1-to-v2.md`).
- `@`-импорты — через пустую строку (подряд идущие `@~/…` Markdown-превью показывало зачёркнутыми).
