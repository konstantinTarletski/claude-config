# Правила ведения документов

AI-часть — обёртка кита `<проект>-ai1st`. Код — в репозиториях частей (бэкенд, фронтенд, e2e); в обёртке они
ссылками в `project-repos/`.

- Все рабочие документы (планы тестов, отчёты, проблемы части) — в репозитории своей части (бэкенд, фронтенд, e2e), в
  ветке, где идёт работа.
- В AI-части — `docs/README.md`: какая работа в какой ветке, насколько сделано, что уже сделано («заново не
  начинать»), какой документ где смотреть.
- У части ещё нет рабочей ветки → её документы пока лежат в AI-части; где они — в `docs/README.md`; с первой
  рабочей веткой переезжают в репозиторий части.

## 1. Где что лежит

**AI-часть, `docs/`** — то, что про проект целиком:

| Файл | Что в нём |
|---|---|
| `README.md` | что происходит — «2. `docs/README.md` AI-части» |
| `documents_ru.md` | правила ведения документов — этот файл |
| `terms_ru.md`, `key-parts-flow_ru.md`, `backend-test-flow_ru.md`, `backend-test-rules_ru.md` | правила проекта: термины, flow ключевых частей, flow и цель для бэкенд-тестов |
| `key-parts.md` | ключевые части системы — результат `key-parts-flow_ru.md` |
| `project-issues.md` | проблемы самой AI-части и сразу нескольких частей |
| `tests/README.md` | правила для всех планов тестов и ссылки на планы частей |
| `project-audits/` | аудиты проекта: `audit-report-<ГГГГ-ММ-ДД>.md` |

**Репозиторий части, `docs/`, в ветке работы** — то, что про эту часть; меняется в том же коммите, что и код, после
merge уходит в `main` вместе с ним:

| Файл | Что в нём |
|---|---|
| `tests/backend-plan-<шаг или тема>-<ГГГГ-ММ-ДД>.md` | план работы по тестам — `backend-test-flow_ru.md → 4. План и работа → 4.3` |
| `tests/backend-violations-<ГГГГ-ММ-ДД>.md` | отчёт по нарушениям — `backend-test-flow_ru.md → 3. Отчёты → 3.1` |
| `tests/backend-report.md` | общий отчёт — `backend-test-flow_ru.md → 3. Отчёты → 3.2` |
| `tests/frontend.md`, `tests/e2e.md` | план тестов фронтенда и e2e |
| `project-issues.md` | проблемы этой части; строка `Tests:` — тест, который её закрепляет; тесты на удаление |

**Проблемы проекта:**
- Проблема одной части → в `project-issues.md` этой части: бэкенд — в бэкенде, фронтенд — во фронтенде, e2e — в
  e2e.
- В AI-части — проблемы самой AI-части и проблемы сразу нескольких частей (двух или всех трёх: бэкенд, фронтенд,
  e2e); вверху — ссылки на `project-issues.md` бэкенда, фронтенда и e2e.
- Файл проблем есть всегда, у каждой части и в AI-части; проблем нет → «Не обнаружено, проверено <ГГГГ-ММ-ДД>».

**Планы тестов:**
- План и отчёты части → в `tests/` этой части: бэкенд — в бэкенде, фронтенд — во фронтенде, e2e — в e2e.
- В AI-части — `tests/README.md`: правила для всех планов и ссылки на `tests/` бэкенда, фронтенда и e2e.

## 2. `docs/README.md` AI-части

Только то, чего нет в других документах. Что где лежит — `documents_ru.md`, правила — `terms_ru.md`,
`key-parts-flow_ru.md`, `backend-test-flow_ru.md`, `backend-test-rules_ru.md`: в README на них ссылка, не пересказ.

```text
# <Проект>: что происходит

Обновлено: <ГГГГ-ММ-ДД>. Что где лежит — documents_ru.md.

## В работе
| Работа | Репозиторий | Ветка | MR | Сделано | Где смотреть |

## Сделано — заново не начинать
| Работа | Где теперь (ветка, дата merge) | Итог |

## Дальше
| Работа | Когда |

## Проблемы проекта
| Часть | Репозиторий | Ветка | Открыто | Файл |

## Решения проекта
Только то, что есть лишь у этого проекта: порядок работы, решения команды.
```

Когда обновлять (и дату в шапке — при каждой правке):
- новая работа или новая ветка → строка в «В работе»;
- в плане поставили галочку → «Сделано» (`<N> из <M>`);
- открылся MR → колонка «MR»;
- ветку смёрджили → строка переезжает в «Сделано — заново не начинать», ссылка на итог — в `main`;
- в репозитории части появилась или закрылась проблема → «Проблемы проекта», колонка «Открыто».
