# Термины

Общие для правил проекта: `key-parts-flow_ru.md`, `backend-test-flow_ru.md`, `backend-test-rules_ru.md`.

- **Ключевая часть** — без которой не пройти основные пути системы и люди не могут нормально работать (сломался
  вход, не сохраняются главные объекты), либо та, ошибка в которой:
  - стоит денег или имеет юридические последствия (расчёты, суммы, отчёты государству);
  - портит данные, которые потом трудно исправить;
  - уходит наружу (обмен с другими системами);
  - пропускает того, у кого нет прав;
  - случается без человека, и её сразу никто не заметит (планировщики).

  По важности — critical или major. Список — `key-parts-flow_ru.md`.
- **Важность части:**
  - critical — без неё не пройти основной путь; деньги, юридические последствия, порча данных, права;
  - major — работать можно, но сильно сложнее или только с обходом;
  - minor — неудобно, но работе не мешает.
- **Основной путь** — то, ради чего системой пользуются каждый день; список берём из спеки или у аналитика.
- **Бизнес-логика** — сервисы: код, где обрабатываются данные. Не считаются: контроллеры, мапперы, конфигурация,
  сгенерированный код. SQL в покрытие не входит, даже со сложной логикой: инструмент покрытия (JaCoCo) его не видит;
  такой SQL проверяет тест SQL (`backend-test-rules_ru.md → 1. Все тесты → 1.2`).
- **Сложный хелпер** — хелпер с ветвлениями или расчётом, который вызывают из нескольких мест.
