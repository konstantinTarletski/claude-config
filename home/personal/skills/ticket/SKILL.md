# Работа над тикетом

Общий порядок для всех проектов. Всё проектное — адрес трекера, переменная с токеном, ветка,
стиль коммита, где искать код, как тестировать, калибровка оценок — в разделе **«Задачи»**
`CLAUDE.md` текущего проекта. Прочитать его первым делом; если раздела нет — спросить параметры
и завести раздел.

Не пропускать шаги 2 и 3 — на них чаще всего экономят и потом переделывают.

## 1. Вытащить тикет

Не тянуть весь JSON в контекст — нужен только текст (`<JIRA>`, `<TOKEN_VAR>` — из раздела «Задачи»):

```bash
curl -sS -H "Authorization: Bearer $<TOKEN_VAR>" \
  "<JIRA>/rest/api/2/issue/<KEY>?fields=summary,description,status,assignee,reporter,priority,comment,issuelinks,labels,attachment" \
  | python3 -c "
import json,sys
f=json.load(sys.stdin)['fields']
print('STATUS:', f['status']['name'], '| PRIORITY:', (f.get('priority') or {}).get('name'))
print('ASSIGNEE:', (f.get('assignee') or {}).get('displayName'), '| REPORTER:', (f.get('reporter') or {}).get('displayName'))
print('SUMMARY:', f['summary'])
print('\n--- DESCRIPTION ---\n', f.get('description'))
for c in f['comment']['comments']:
    print(f\"\n--- COMMENT {c['created'][:10]} {c['author']['displayName']} ---\n{c['body']}\")
for l in f.get('issuelinks', []):
    i = l.get('inwardIssue') or l.get('outwardIssue') or {}
    print('LINK:', l['type']['name'], i.get('key'), i.get('fields',{}).get('summary'), i.get('fields',{}).get('status',{}).get('name'))
for a in f.get('attachment', []): print('ATTACH:', a['filename'], a['content'])
"
```

Если переменная с токеном пустая — см. `gotchas.md` («Переменная из `~/.bashrc` пустая»).
Описание и все комментарии — **перевести на русский**. Последний комментарий аналитика часто
важнее описания: он сужает объём. Посмотреть связанные задачи (`LINK`) — например, парную на
фронте/бэке.

## 2. Вложения и wiki

Скачать вложения в scratchpad (тем же заголовком `Authorization`) и посмотреть. Скриншоты и макеты
снимают вопросы, которые иначе ушли бы аналитику. Ссылки на wiki — забрать через REST API wiki
(адрес и токен — в разделе «Задачи»; токен wiki обычно отдельный от трекера).

## 3. Завести документ по задаче

```bash
mkdir -p .claude/tickets && cp ~/.claude/personal/templates/ticket.md .claude/tickets/<KEY>.md
```

Сразу, и дописывать по ходу, а не в конце по памяти. Главное в нём — **почему выбран именно этот
вариант**, что оставлено и с чем пересекается. Требования — `workflow.md`, «Документ по задаче».

## 4. Не сделано ли уже

Поиск по коду ключевых слов тикета, `git log --all --grep=<KEY>`, ветки `*<KEY>*`. Часть задач
возвращается из тестирования с мелкой правкой; бывает, что похожее уже делали и убрали — тогда
код лежит в истории.

## 5. Найти место правки

Трассировать от входной точки (экран / контроллер) до строки, где рождается нужное поведение.
Посмотреть, сколько **других** мест использует ту же функцию — правка может задеть больше, чем
просит тикет; если это консистентно — делать и одной строкой сказать, что ещё изменилось и как
откатить. Особенности проекта — в «Задачах».

## 6. Оценка

Скилл `/estimate` — три цифры. Калибровочные прецеденты проекта — в «Задачах».

## 7. Реализация и проверка

- Ветка — по разделу «Задачи» (создаёт пользователь, если он так делает).
- Тесты: сначала точечно, потом полный прогон; убедиться, что новые тесты реально запустились.
- Команды и особенности (генерация кода, форматтер, миграции) — в `CLAUDE.md` / `gotchas.md` проекта.

## 8. Коммит

Сообщение — в стиле из «Задач», текст не на русском — с переводом. Коммитит пользователь сам:
дать ему точный список файлов по каждому репозиторию.
