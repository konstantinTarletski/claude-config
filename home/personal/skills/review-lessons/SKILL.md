# Проверка кода по урокам ревью

Правила уже в контексте (`tech/*.md`); здесь — порядок.

## Проверка (перед коммитом)

1. Взять `CODE.RULE` и `RULE` технологий из диффа (`tech/java.md`, `tech/ng.md` …), с учётом меток версий
   (`RULES.VER.1`), + те же номера в `<repo>/.claude/tech/*.md` и **прошлые замечания `<repo>/.claude/review.md`**.
2. Пройти каждый пункт по `git diff` каждого репозитория → нарушение исправить; оставлено сознательно → «Неочевидное в
   коде» (`/ticket`, шаг 4).

## Урок (`add`)

1. Строкой в `<repo>/.claude/review.md` (`WORK.REVW.1`); нет файла — завести и подключить `@.claude/review.md` в
   `<repo>/CLAUDE.md`.
2. Урок общий → строкой в `CODE.LOG` (`tech/code.md`): что спросили → урок общими словами → номер правила.
3. Нужно новое правило → в `RULE` своей технологии; общие правила — только после «меняй» (`RULES.EDIT.1`). Имя
   ревьюера, его привычки, конкретные классы — в проект.
