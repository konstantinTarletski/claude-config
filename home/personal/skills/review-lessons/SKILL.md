# Проверка кода по правилам

Сами правила — в `~/.claude/personal/tech/*.md` (подключены через `@`, уже в контексте); здесь только порядок.

## Перед отдачей на коммит

1. Взять `CODE.RULE` и разделы `RULE` технологий, которых касается дифф (`tech/java.md`, `tech/ng.md` …), с учётом
   меток версий (`RULES.VER.1`).
2. Пройти каждый пункт против диффа задачи (`git diff` по каждому репозиторию): нарушение — исправить; осталось в коде
   сознательно — в «Неочевидное в коде» (`WORK.DONE.2`).
3. Проектное — те же номера в `<repo>/.claude/tech/*.md`, `<repo>/.claude/work.md` и **замечания прошлых ревью —
   `<repo>/.claude/review.md`** (`WORK.REVW.2`).

## После замечания ревьюера (`add`)

1. Строкой в `<repo>/.claude/review.md` (`WORK.REVW.1`); нет файла — завести и подключить `@.claude/review.md` в
   `<repo>/CLAUDE.md`.
2. Урок общий — строкой в `CODE.LOG` (`tech/code.md`): что спросили → урок общими словами → номер правила
   (существующего или нового).
3. Новое правило — в `RULE` своей технологии (`tech/<тех>.md`, новая технология — новый файл по `RULES.NEW.1`);
   менять общие правила — по `RULES.EDIT.1` (предложить текст и номер, ждать «меняй»). Проектная специфика (имя
   ревьюера, его предпочтения, конкретные классы) — в проект.
