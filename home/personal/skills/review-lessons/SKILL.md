# Уроки с ревью

Чек-лист собран из реальных замечаний ревьюеров. Здесь — только общее (переносимое); что конкретный ревьюер или
проект требует сверх этого — в `<repo>/CLAUDE.md` → «Задачи» / `<repo>/.claude/gotchas.md`.

## Перед отдачей на коммит — пройти по пунктам

1. **Где живёт код.** Логика для сущности из внутренней библиотеки (общий `core`/`common`-модуль) — там же, где у
   соседних сущностей такая же логика. Посмотреть, как сделан ближайший аналог: если у него фильтр/репозиторий/сервис
   в библиотеке — новый тоже туда (а не в приложение), даже если в библиотеку нет доступа — тогда сказать об этом
   заранее, а не после ревью.
2. **Каждая неочевидная строка — либо доказана, либо убрана.** Явная настройка, которая «кажется нужной» (явный
   маппинг поля, лишняя аннотация, защитная проверка), — проверить экспериментом: убрать → собрать → посмотреть
   результат. Не подтвердилось — не добавлять. Ревьюер спросит «зачем», и ответ «на всякий случай» не годится.
3. **Выбор API/подхода, по которому в проекте нет стандарта** (например, `nanoTime` vs `currentTimeMillis`) — иметь
   готовый ответ: где в проекте сделано так же + ссылка на первоисточник (документация, исходники).
4. **Неочевидное — объяснено заранее.** Всё из пунктов 2–3, что осталось в коде, — перечислить пользователю отдельным
   блоком при сдаче задачи (`workflow.md` → «Неочевидное в коде — отдельным блоком»), чтобы он мог ответить ревьюеру
   сразу или убрать до PR.

## После замечания ревьюера — пополнить

Получили замечание — одной строкой: что спросили → какой урок (общими словами) → пункт выше или новый пункт.
Проектная специфика (имя ревьюера, его предпочтения, конкретные классы) — в проект, не сюда.

## Журнал (кратко, без имён и проектов)

- Фильтр/репозиторий для сущности из внутренней библиотеки сделали в приложении → «должно быть в библиотеке» (п. 1).
- Явный `@Mapping` для поля, которое MapStruct маппит сам → «зачем перечислены поля» (п. 2).
- `System.nanoTime()` для замера длительности → «зачем наносекунды» — ответ: монотонность, а не точность (п. 3).
