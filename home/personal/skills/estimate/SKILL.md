# Оценка задачи

Часы — от старта до передачи на Code Review (тест, деплой, приёмка не входят).

```text
№1  сеньор, плохо знающий проект  → цифра наружу (Jira, тимлид, аналитик)
№1a сеньор, знающий проект         → сколько ушло бы у «своего» без ассистента
№2  реально ушло у нас (я + ассистент, со всеми граблями) → калибровка №1
№3  чистый кодинг (уже известно, что и где менять)        → нижняя граница
```

**№1, №1a, №2 — всегда двумя частями:** разбор (тикет, спека, место в коде, решение, вопросы) + реализация (код,
тесты, проверка, PR). Для №2 граница — момент «делай».

Мне — **таблицей**, части отдельными колонками (не «2.5h (1.5 + 1)»):

| # | Кто | Разбор | Реализация | Итого |
|---|---|---|---|---|
| 1 | Сеньор без знания проекта | 1.5h | 1h | 2.5h |

## План и факт

- **План** → после разбора, до «делай»: №1, №1a, №2 (сколько, думаем, уйдёт у нас), №3 → сразу в документ задачи
  и больше не менять, даже если ошиблись.
- **Факт** → вместе со списком на коммит: №2 по сессии, №3 по реальному диффу, №1 — переоценка, зная реальную
  сложность.
- **Сравнение** → «план | факт | отклонение» по каждой цифре + одна-две строки, почему разошлось. Вывод, который
  меняет будущие оценки, — в калибровку проекта.

## Как считать

- **№1:** 2–3 похожих прошлых задачи из калибровки (`WORK.EST.101` проекта): списано в трекере + объём из git
  (`git log --all --grep=<KEY> --no-merges --numstat`, без генерённого) → таблица «задача | репо | файлы | +/− |
  списано» → этапы (разбор / код / тесты / проверка) со ссылками `файл:строка` → цифра + диапазон.
- **№2:** `~/.claude/personal/tools/session-time.py --go делай -- <каталог проекта в ~/.claude/projects> <KEY>` →
  разбор и реализация (паузы > 20 мин не считаются). Добавить то, что я делал вне сессии (ручная проверка, коммит) и
  фоновые прогоны, которых ждали, — спросить, если не видно.

## Где хранить

Документ задачи → раздел «Оценка»: три цифры, прецеденты, после закрытия — факт. Калибровка проекта → строка в
`WORK.EST.101` (`<repo>/.claude/work.md`); здесь — не держать.
