# Оценка задач

## Три цифры

Каждая оценка — **три числа в часах**, от старта до передачи на Code Review (тестирование,
деплой и приёмка не входят):

| # | Что | Для чего |
|---|---|---|
| 1 | **Сеньор, плохо знающий проект** | Цифра «наружу» — для Jira, тимлида, аналитика |
| 1a | **Сеньор, знающий проект** | Сколько ушло бы у «своего» разработчика без ассистента |
| 2 | **Реально ушло у нас** (я + ассистент) — со всеми костылями, граблями, разбором | Калибровка: насколько оценка №1 расходится с жизнью |
| 3 | **Чистый кодинг** — написать изменения, когда уже известно, что и где менять | Нижняя граница, показывает долю «вокруг кода» |

**№1, №1a и №2 — всегда двумя слагаемыми**, потому что разбор часто занимает столько же или больше, чем код:
- **разбор** — вникнуть в тикет и спеку (перевод, вложения, wiki, диаграммы), найти место в коде, понять текущую
  логику и соседние места, выбрать решение, задать вопросы;
- **реализация** — код, тесты, прогоны, ручная проверка, PR.

Для №2 граница — момент «делай»: до него разбор, после — реализация (по таймстемпам сессии).

**Формат — таблица, разбор и реализация отдельными колонками**, без записей вида «2.5h (1.5 + 1)»:

| # | Кто | Разбор | Реализация | Итого |
|---|---|---|---|---|
| 1 | Сеньор без знания проекта | 1.5h | 1h | 2.5h |

План и факт — две такие таблицы (или колонки «План» / «Факт» внутри каждой части), отклонение — по итогу.

Аудитория цифры №1 — **временная договорённость** (с 2026-09-25), потом будем её сдвигать. При
смене — править здесь.

## Две оценки: план и факт

По каждой задаче (с 2026-09-30; для задач, начатых раньше, не переделывать) — **две оценки всех трёх цифр**:

1. **План — до реализации**, как только понятно, что и где менять (после разбора, до «делай»): №1, №2 (сколько,
   думаем, уйдёт у нас) и №3. Записать в документ задачи **сразу** и больше не менять — даже если потом выяснится,
   что ошиблись.
2. **Факт — после реализации**, вместе со списком файлов на коммит: №2 по таймстемпам сессии; №3 — по реальному
   диффу; №1 — переоценка «сколько ушло бы у сеньора без знания проекта, зная теперь реальную сложность».
3. **Сравнение** — таблица «план | факт | отклонение» по каждой цифре и одной-двумя строками **почему разошлось**
   (не учли места правки, грабли окружения, долгое ревью…). Вывод, который меняет будущие оценки, — в калибровку
   проекта.

## Как считать №1

1. Взять 2–3 похожих прошлых задачи: **списанное время** из трекера и **объём** из git
   (`git log --all --grep=<KEY> --no-merges --numstat`, без генерённого кода).
2. Показать таблицу прецедентов: задача | репо | файлы | +/− строк | списано.
3. Разбить на этапы — **разбор** (вход в проект, тикет, спека, поиск места, понимание логики) / код / тесты /
   ручная проверка и ревью — со ссылками `файл:строка` на то, что придётся понять или поменять.
4. Одна цифра + диапазон, разбор и реализация отдельно. Так же — №1a для того, кто проект знает (у него короче
   в основном разбор).

## Как считать №2

По таймстемпам сессии (`~/.claude/projects/<проект>/<session>.jsonl`): суммировать активные
интервалы (паузы > 20 мин — перерыв), отдельно от разговоров не по задаче. Добавить время,
которое я тратил сам вне сессии (локальный запуск, ручная проверка, коммит) — спросить, если
не видно.

Скрипт: разбор — от сообщения со ссылкой на тикет до «делай», реализация — от «делай» до конца. Подставить
`<проект>` (каталог в `~/.claude/projects/`) и маркеры — фрагменты текста сообщений пользователя:

```bash
python3 - <<'EOF'
import json, glob, os
from datetime import datetime
f = max(glob.glob(os.path.expanduser('~/.claude/projects/<проект>/*.jsonl')), key=os.path.getmtime)
rows = []
for line in open(f, encoding='utf-8'):
    try: d = json.loads(line)
    except ValueError: continue
    if not d.get('timestamp'): continue
    t = datetime.fromisoformat(d['timestamp'].replace('Z', '+00:00'))
    c = d.get('message', {}).get('content') if d.get('type') == 'user' else ''
    txt = c if isinstance(c, str) else ' '.join(x.get('text', '') for x in c if isinstance(x, dict)) if isinstance(c, list) else ''
    rows.append((t, txt))
rows.sort(key=lambda r: r[0])
def active(a, b):  # паузы > 20 мин не считаются
    ts = [t for t, _ in rows if a <= t <= b]
    return round(sum((q - p).total_seconds() for p, q in zip(ts, ts[1:]) if (q - p).total_seconds() < 1200) / 3600, 2)
start = next(t for t, x in rows if '<KEY>' in x and 'browse' in x)   # ссылка на тикет
go = next(t for t, x in rows if t > start and '<маркер «делай»>' in x)
print('разбор', active(start, go), 'реализация', active(go, rows[-1][0]))
EOF
```

Фоновые прогоны (сборка, тесты) идут без записей в сессию — их длительность добавить отдельно, если ждали.

## Где хранить

В документе по задаче (см. `workflow.md`), раздел «Оценка»: все три цифры, таблица прецедентов,
после закрытия — факт. Калибровочные данные конкретного проекта (прецеденты) держать в проекте,
а не здесь.
