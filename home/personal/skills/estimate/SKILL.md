# Оценка задач

## Три цифры

Каждая оценка — **три числа в часах**, от старта до передачи на Code Review (тестирование,
деплой и приёмка не входят):

| # | Что | Для чего |
|---|---|---|
| 1 | **Сеньор, плохо знающий проект** | Цифра «наружу» — для Jira, тимлида, аналитика |
| 2 | **Реально ушло у нас** (я + ассистент) — со всеми костылями, граблями, разбором | Калибровка: насколько оценка №1 расходится с жизнью |
| 3 | **Чистый кодинг** — написать изменения, когда уже известно, что и где менять | Нижняя граница, показывает долю «вокруг кода» |

Аудитория цифры №1 — **временная договорённость** (с 2026-09-25), потом будем её сдвигать. При
смене — править здесь.

До начала работы известна только №1 (и прикидка №3). №2 дописывается по факту после завершения.

## Как считать №1

1. Взять 2–3 похожих прошлых задачи: **списанное время** из трекера и **объём** из git
   (`git log --all --grep=<KEY> --no-merges --numstat`, без генерённого кода).
2. Показать таблицу прецедентов: задача | репо | файлы | +/− строк | списано.
3. Разбить на этапы — вход в проект / код / тесты / ручная проверка и ревью — со ссылками
   `файл:строка` на то, что придётся понять или поменять.
4. Одна цифра + диапазон. Одной строкой — сколько выйдет у того, кто проект знает.

## Как считать №2

По таймстемпам сессии (`~/.claude/projects/<проект>/<session>.jsonl`): суммировать активные
интервалы (паузы > 20 мин — перерыв), отдельно от разговоров не по задаче. Добавить время,
которое я тратил сам вне сессии (локальный запуск, ручная проверка, коммит) — спросить, если
не видно.

## Где хранить

В документе по задаче (см. `workflow.md`), раздел «Оценка»: все три цифры, таблица прецедентов,
после закрытия — факт. Калибровочные данные конкретного проекта (прецеденты) держать в проекте,
а не здесь.
