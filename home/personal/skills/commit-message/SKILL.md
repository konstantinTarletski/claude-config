# Сообщение коммита

## Откуда стиль

Формат и язык — из раздела «Задачи» `CLAUDE.md` проекта (строка «Коммит»: шаблон вида `<KEY>: <суть>`, язык).
Нет такой строки — посмотреть 10 последних коммитов (`git log --oneline -10`, без merge) и повторить их стиль; и
одной строкой сказать, что взял из истории.

Ключ задачи — из аргумента, имени ветки (`feature/<KEY>`) или документа задачи. Суть — из диффа и документа
задачи (`<repo>/.claude/tickets/<KEY>.md`), а не по памяти.

## Короткое — по умолчанию

Одна строка: `<KEY>: <что сделано>` — результат для пользователя/системы, а не «как»: «окно детальных данных
крона», а не «добавлен компонент и метод сервиса». Без точки в конце, до ~72 символов.

## Длинное — если попросили «длинный»

```
<короткое сообщение — заголовок>

- <пункт: что изменилось, по слоям/частям — API, экран, тесты>
- <пункт: почему так, если решение неочевидно (выбор из вариантов, обход)>
- <пункт: что сознательно не сделано / сделается в другой задаче>
```

Пустая строка после заголовка; 2–5 пунктов; без путей к файлам (они видны в коммите), без перечисления тестов
поштучно.

## Несколько репозиториев

Задача меняет код в нескольких репозиториях — по сообщению на каждый, с подписью, к какому относится; суть — про
изменения именно этого репозитория.

## Вывод

Каждое сообщение — в блоке ```` ```text ```` (только то, что вставлять). Если сообщение не на русском — сразу под
блоком перевод, отделённый строкой `--------------------` (правило — `rules/communication.md` → «Язык и переводы»):

````
Бэкенд (`<repo>`, ветка `<branch>`):
```text
<сообщение>
```
--------------------
Перевод: «<перевод>».
````
