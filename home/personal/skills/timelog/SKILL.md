# Списание часов

**Только по моему запросу** (обычно в конце дня или недели); сам не предлагать и в остальной работе об этом не думать.

## Настройки проекта

Читать **только при вызове**: `<repo>/.claude/timelog.md` (главного репозитория группы; не `@`-импорт) — только
значения по шаблону `personal/templates/timelog.md`:
- **трекеры:** один (своя фирма) или два (своя + клиента); адреса и токены — `INTG`;
- **задачи:** куда писать; для двух трекеров — пары «задача у нас ↔ задача у клиента» и коэффициент (обычно 1:2);
- **часов в день, точность** (целые / 0.25), **язык описания**;
- **куда можно и нельзя** писать часы — схема фирмы или тимлида (подзадачи, онбординг, оценки);
- **чем переносить** — Atlassian-коннектор (MCP) или `tools/jira-worklog.py`.

Нет файла → спросить значения и завести по шаблону (`FILES.WHERE.9`).

## Куда писать — общее (конкретика — в настройках)

- **Работа без своей задачи** (разбор или оценка другой задачи, инструменты) → в задачу, над которой работали в тот
  момент; другой тикет — пунктом «Looked at tickets <KEY>, <KEY>: …» (на языке описания).
- **Встречи** — не отдельной строкой: пунктом в задаче дня, названием и длительностью («Refinement (30 min)»);
  содержание не выдумывать.
- Не знаю, куда, → спросить одной строкой, не угадывать.

## Журнал

- Файл — `USER.FOLD.1`, простой текст, **общий для всех проектов**: новые дни сверху; день есть → менять только строки
  своего проекта. Правлю и я → перед правкой перечитать, мои правки не трогать.
- Формат — один трекер / два трекера:
  ```
  <ДД.ММ>
  <задача>        -- <часы>
                  - <пункт описания>

  <ДД.ММ>
  <задача у нас>/<задача у клиента>    -- <часы у нас>/<часы у клиента>
                                         - <пункт описания>
  ```
- **День = ровно часы из настроек**, пока я не скажу иначе про этот день. **Сумму каждого дня проверять всегда** —
  после правки журнала, перед показом и перед переносом, в том числе дни, записанные другой сессией. Не сходится →
  не переносить: больше — срезать с задачи, где работы меньше всего, меньше — добавить задаче по реальной работе;
  сказать, какую. Урезал часы одного тикета → освободившееся сразу отдать другому тикету того же дня и сказать, куда.
- **Пара задач** (два трекера) новая, в журнале её нет → спросить: «Правильно, что `<задача клиента>` у нас —
  `<наша задача>`?».
- **Описание** — на языке из настроек, 1–7 пунктов по строке, конкретно, языком результата. Щедро, но без выдумки:
  включать и невидимую в коммитах работу (разбор спеки и кода, переписка, повторные прогоны, ручная проверка,
  окружение) — только по фактам: документы задач, `git log` за день, сессии. Работу другого дня не переносить. В чат —
  с переводом (`COMM.LANG.3`), в журнал — без перевода.
- Дни, уже перенесённые в трекер, не менять без прямой просьбы.

## Перенос в трекер — только после «переноси» (`INTEG.ALL.1`)

Сначала журнал, я подтвердил → потом трекер.

1. **Ограничения доступа фирмы** (managed policy, списки запретов) — соблюсти до первого запроса.
2. **Что уже есть** — worklog'и задач за эти дни. Мои (по автору) уже есть → не задваивать, показать разницу. Чужие
   (коллеги, интеграции вроде Tempo) — не трогать и не считать.
3. **Сумма каждого дня** = часы из настроек («Журнал»), иначе стоп. **Записать** — тот же день (начало 00:00
   местного), те же часы, тот же текст (пункты журнала списком). Два трекера — один в один: в свой — часы «у нас»,
   клиенту — «у клиента».
4. **Перечитать** и сверить с журналом по дням; мне — таблица «день — задачи — часы».
5. **Расходится** → в трекере само не править: показать разницу, решаю я (сначала журнал). Своя запись — правкой (часы,
   текст). **Удалить** — делаю я сам (необратимое удаление ассистенту нельзя): дать путь в интерфейсе; после «удалил» —
   перечитать и сверить.

Чем переносить:
- **Atlassian-коннектор (MCP):** `discover` → `listJiraIssueWorklogs` (`executeRead`; `startedAfter` / `startedBefore` —
  мс, сутки по местному времени) и `addOrEditJiraIssueWorklog` (`executeWrite`; `issueIdOrKey`, `timeSpent` `2h`,
  `started` `<дата>T00:00:00.000+0200`, `comment` — пункты `* …`; с `worklogId` — правка своей записи).
- **`tools/jira-worklog.py`** — только для журнала с двумя трекерами: берёт строки дня из журнала, без `--post` показывает
  и сверяет («совпадает» / «РАСХОДИТСЯ» / «ЕСТЬ В JIRA, НЕТ В ЖУРНАЛЕ»); `--post` — по одному дню, потом прогон без
  `--post` ещё раз:
  ```text
  ~/.claude/personal/tools/jira-worklog.py <ДД.ММ> --journal <журнал, USER.FOLD.1> --ours <задача у нас> \
    --side ours|client --url <Jira> --token-env <ТОКЕН> [--email <e-mail>] --zone <пояс, USER.SYS>
  ```

## Таблица часов (для тимлида)

Строки — задачи, колонки — дни, итоги; колонки выровнять скриптом; в мессенджер — внутри блока кода (```), иначе
разъедется. Под таблицей — одной строкой, что за задачи.

```
Ticket       02.11  03.11  Total
--------------------------------
<KEY-1>         2h     4h     6h
<KEY-2>         6h     4h    10h
--------------------------------
Total           8h     8h    16h
```
