# Переезд с claude-config v2.0 на v2.1 — профиль `USER`

Читать при переезде (`RULES.MIGR.2`), не грузится всегда. Собрано по `git diff v2.0..v2.1` (15.10.2026). Образец —
профиль `personal/users/tarlekon_askend.md` и проект `resource-be`. Что поменялось — `CHANGELOG.md`, раздел 2.1.

**С v1 сразу на 2.1** — подряд: сначала `v1-to-v2.md` целиком (кроме метки `2.0` — её не ставить), потом этот файл; в
конце — одна метка `2.1`. То, что `v1-to-v2.md` относит к фактам о пользователе (старые `environment.md`, «про меня» в
`CLAUDE.md` / `tasks.md` проекта), — сразу в профиль `USER`, не в правила v2.

## 1. Что изменилось

- **Профиль `USER`** — `personal/users/<имя>_<фирма>.md`; активный — симлинк `~/.claude/user.md` (не в git),
  подключён в `~/.claude/CLAUDE.md` первым импортом (`RULES.USER.1`). В нём — всё «про меня»: `ABOUT`, `PREF`, `WORK`,
  `PERM`, `SYS`, `DEV`, `ACC`, `FOLD`, `EVENT`, `MORE`.
- **Правила ссылаются на профиль** вместо своих фактов о пользователе (`COMM.LANG.1/2/6`, `COMM.BRIEF.1`,
  `COMM.LEARN.1/2`, `WORK.TICK.1`, `WORK.DISC.4/6`, …). Номера правил **не менялись** — ссылки проектов работают.
- **`PROJ.EVENT`** — новый раздел проекта: стендапы, демо, спринт (`RULES.PROJ.6`).
- Память ассистента — только контекст разговоров; факты о пользователе — в `USER`, события проекта — в `PROJ.EVENT`
  (`FILES.WHERE.1`).

## 2. На машине (один раз)

1. `git pull` в `claude-config` → `./install.sh`.
2. Профиль: есть свой `personal/users/<имя>_<фирма>.md` — `./install.sh` выберет его (несколько — спросит или
   `--profile <имя>`). Нет — создать копией чужого, переписать **все** разделы и снова `./install.sh` (`SYS`, `DEV` — проверить командами:
   `cmd.exe /c "wsl --version"`, `java -version`, `node -v`, `git --version`, `docker ps`, `.wslconfig`, часовой пояс).
3. **Память** (`~/.claude/projects/*/memory/`): каждую запись — факт о пользователе (язык, привычки, цель, уход,
   распорядок) → в `USER` (событие проекта → `PROJ.EVENT` проекта), запись удалить **отдельной командой**
   (`SAFE.DESTR.1`), в `MEMORY.md` — строка-ссылка на номер. Правило работы (не факт) — проверить, есть ли в
   `rules/`; нет — дописать туда (`RULES.EDIT.1`), не терять.

## 3. В каждом проекте

1. Проект на v1 — сначала `v1-to-v2.md`.
2. `grep -rniE "по-русски|русск|IntelliJ|транслит|C:\\\\Users|SHARED|стендап|уход" <repo>/CLAUDE.md <repo>/.claude
   --include=*.md --exclude-dir=tickets` — факты о пользователе: общий факт → `USER` (в проекте — ссылка на номер);
   устройство самого проекта (как его запускают, путь JDK в команде) — оставить, можно добавить ссылку на `USER.DEV`.
3. События проекта из памяти и документов (стендап, демо) → `PROJ.EVENT`: один проект — в `<repo>/CLAUDE.md`;
   связанные репозитории — в общем файле главного, рядом с `PROJ.TEAM` (`<главный>/.claude/work.md`, `RULES.PROJ.8`),
   иначе второй их не увидит.
4. Утверждения об окружении, ставшие неправдой (например, «Docker из WSL не виден» — после включения интеграции),
   — поправить с датой и ссылкой на `USER`.
5. **Группа репозиториев** (бэк + фронт, проекты одного клиента): у **каждого** свой `CLAUDE.md`, даже без своих
   правил — тонкий: метка, `PROJ.ABOUT` в пару строк, `@`-ссылки на главный (`RULES.PROJ.8`); скрыть
   `/CLAUDE.md` в `.git/info/exclude`; в главном — дописать, кто подключает. Порядок и раскладка `@`-ссылок — как в
   `v1-to-v2.md` (§2 п. 3, §4 п. 1), здесь не повторяем. Образец — `baasmoodulid`, `eteenindus` → `../dire`.
6. Метка версии — первая строка `<repo>/CLAUDE.md`: `<!-- claude-config: 2.1 -->`.

## 4. Проверка

1. В правилах (`~/.claude/CLAUDE.md`, `personal/`) нет фактов о конкретном человеке:
   `grep -rniE "по-русски|бэкенд сильн|IntelliJ|SHARED|лень" ~/.claude/CLAUDE.md ~/.claude/personal --include=*.md
   --exclude-dir=users` — только упоминания инструментов в граблях. Местоимения «я / мне» остаются — это хозяин
   профиля.
2. Все ссылки `USER.*` существуют: `grep -rho "USER\.[A-Z]\{3,5\}\.[0-9]\+" ~/.claude/personal <repo>/.claude | sort -u` —
   каждый номер есть в профиле.
3. Новая сессия: ассистент знает факты профиля (`USER.PREF.3` и т. п.), не открывая файл, — значит импорт работает.
4. Пользователю — таблицей: что переехало в `USER` / `PROJ.EVENT`, что удалено из памяти.
