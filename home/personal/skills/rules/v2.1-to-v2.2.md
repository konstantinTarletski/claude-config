# Переезд с claude-config v2.1 (и 2.1.1) на v2.2 — шаблоны, профиль и фирма вне git

Читать при переезде (`RULES.MIGR.2`), не грузится всегда. Образец — `resource-be` (пара бэк + фронт) и `dire` (группа из 5
репозиториев). Что поменялось — `CHANGELOG.md`, раздел 2.2. С v2.0 и раньше — сначала `v2.0-to-v2.1.md`.

## 1. Что изменилось

- **`claude-config` публичный** — личное в нём больше не хранится: `home/personal/users/*.md` (профиль) и
  `home/personal/firms/*.md` (фирма) — в `.gitignore`. В git — только шаблоны `personal/templates/user.md`, `firm.md`.
- **Профиль `USER`** — по шаблону `templates/user.md`; пункты с «◆» — на них ссылаются правила, держать их всегда.
  Доступы к системам из профиля ушли в `FIRM` (`USER.ACC.1` — ссылка); в профиле — только доступы машины (CA, VPN).
- **Файл фирмы `FIRM`** (`RULES.USER.2`) — `personal/firms/<фирма>.md`, подключён `@` из профиля:
  `FIRM.OWN` — своя фирма (трекер, почта, учёт часов), `FIRM.<КЛИЕНТ>.1` — проекты с синонимами и репозитории,
  `FIRM.<КЛИЕНТ>.2` — системы: есть / нет доступа / не проверено, адрес, имя токена, утилита, где подробности.
  Вести сразу: появилось — дописать, сломалось — исправить, убрали — удалить.
- **`INTEG` проекта** — только рецепты (готовые команды, номера, таблицы логов, грабли) со ссылкой на `FIRM.<КЛИЕНТ>.2`;
  описания систем («Jira — адрес, проект», «токен такой-то») — в `FIRM`.
- **`timelog-askend.md`** проекта — без адресов и токенов Jira (они в `FIRM`), только проект, задачи, часы.
- `install.sh` — нет профиля → подсказывает шаблон; проверяет, что файл фирмы из профиля существует.

## 2. На машине (один раз)

**Профиль человека не должен потеряться** — после 2.2 его нет ни в git, ни на GitHub, копия только у него. Любое
переключение на версию до 2.2 (`switch`, `checkout`, старый тег) тоже стирает его — `GIT.TRAP.4`. Ассистент,
который ведёт переезд, **не делает `git pull`, пока копия не снята и не проверена**.

1. **Копия до всего остального** — все личные файлы, в git они или нет:
   `mkdir -p ~/claude-personal-<дата> && cp -v home/personal/users/*.md home/personal/firms/*.md ~/claude-personal-<дата>/`
   (`firms/` до 2.2 нет — ошибку про неё пропустить). Проверить: `ls -la ~/claude-personal-<дата>` — размеры не нулевые,
   число файлов совпадает с `ls home/personal/users`. Пользователю — одной строкой, где копия.
2. `git pull` — профиль автора и, если был, свой профиль из git **удалятся из папки** (удалены из репозитория). Сразу
   `ls home/personal/users`: своего нет — вернуть из копии (`cp ~/claude-personal-<дата>/<имя>_<фирма>.md
   home/personal/users/`); git его больше не видит (`git status --ignored` — `!!`).
3. `./install.sh` — должно быть «= …/users/<имя>_<фирма>.md» и «= …/firms/<фирма>.md», без «!».
4. **Дальше бэкап — на человеке**: профиль и файл фирмы — копией вне репозитория (облако, внешний диск). Новая машина или
   новое место репозитория — сначала перенести их, потом `./install.sh`. Копию `~/claude-personal-<дата>` удалить
   только после его «да».

## 3. Профиль по шаблону

1. Открыть рядом свой профиль и `templates/user.md`. Разделы и номера — как в шаблоне; пункт «◆» отсутствует —
   дописать (хотя бы «нет»); свои пункты — оставить своими номерами. Номер убранного пункта не переиспользовать
   (`RULES.CODE.2`).
2. Из `USER.ACC` и других разделов вынести в файл фирмы всё про фирму и клиентов: имена токенов, адреса трекеров и
   wiki, плагины и почту фирмы. `USER.ACC.1` — ссылка «в `FIRM`».
3. В шапке профиля — строка `@~/.claude/personal/firms/<фирма>.md` (отдельной строкой, через пустые строки вокруг).

## 4. Файл фирмы

1. `cp templates/firm.md firms/<фирма>.md`.
2. `FIRM.OWN.1` — системы своей фирмы.
3. На каждого клиента — раздел `FIRM.<КЛИЕНТ>` (код 3–5 латинских букв) с синонимами: `.1` — проекты и репозитории
   (какой главный в группе, `RULES.PROJ.8`), `.2` — системы. Источники: `INTEG` проектов, профиль (`USER.ACC`),
   `timelog-*.md`, `~/.bashrc` (**только имена** переменных: `grep -o "export [A-Z_]*" ~/.bashrc`, `SAFE.SECR.1`).
4. Чего не знаешь — «не проверено», не выдумывать.

## 5. В каждом проекте

1. `grep -rnE "https?://|_TOKEN" <repo>/CLAUDE.md <repo>/.claude --include=*.md --exclude-dir=tickets` — что описывает
   систему (адрес, проект в трекере, имя токена, есть ли доступ) — в `FIRM.<КЛИЕНТ>.2`, в проекте — ссылка; готовые
   команды с адресами — оставить (это рецепт). Адреса страниц wiki, Artifactory в описании сборки — устройство проекта,
   оставить.
2. `INTEG` главного репозитория группы — первая строка: «какие системы, адреса, токены — `FIRM.<КЛИЕНТ>.2`; здесь —
   команды и грабли». Таблица «где лежат доступы» — только доступы **приложений** (настройки, k8s secret); свои — в `FIRM`.
3. `timelog-askend.md` (Askend) — по новому шаблону: строки токенов убрать, «Наша Jira» — проект и ссылка `FIRM.OWN.1`,
   «Jira клиента» — `FIRM.<КЛИЕНТ>.2`.
4. Метка версии — первая строка `<repo>/CLAUDE.md`: `<!-- claude-config: 2.2 -->`.

## 6. Проверка

1. `git -C ~/.claude/claude-config status --short --ignored home/personal` — профиль и файл фирмы в `!!` (игнорируются), в git
   только `.gitkeep` и шаблоны.
2. `./install.sh --dry-run` — «= …/firms/<фирма>.md», без «!».
3. Ссылки на `FIRM.*` существуют: `grep -rho "FIRM\.[A-Z]\{3,5\}\.[0-9]\+" ~/.claude/personal <repo>/.claude <repo>/CLAUDE.md
   | sort -u` — каждый номер есть в файле фирмы.
4. Нет дублей: адреса трекеров и wiki (`grep -rn "jira\.\|confluence\.\|wiki\." <repo>/.claude --include=*.md
   --exclude-dir=tickets`) — только в готовых командах.
5. Новая сессия: ассистент на «какие системы есть у <клиента>» отвечает по `FIRM`, не открывая файлы.
