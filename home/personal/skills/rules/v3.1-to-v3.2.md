# Переезд с claude-config v3.1 на v3.2 — фирмы, люди, проекты, интеграции таблицами

Читать при переезде (`RULES.MIGR.2`), не грузится всегда. Что поменялось — `CHANGELOG.md`, раздел 3.2. С 3.0 и
раньше — сначала `v2.2-to-v3.0.md`.

```text
1 копия старого в private/archive/            (один раз)
2 новые файлы из шаблонов                      (people, projects, integrations; файл фирмы — по новому шаблону)
3 перенести данные                             (по таблице «было → стало»; можно попросить ассистента)
4 профиль: подключить новые файлы
5 старые ссылки FIRM.* → ID                    (grep)
6 проверка
```

## 1. Копия старого

Таблицы — только текущее состояние; история, даты и «почему» остаются в копии.

```bash
mkdir -p ~/.claude/private/archive
cp -r ~/.claude/private/firms ~/.claude/private/archive/firms-$(date +%F)
cp ~/.claude/private/users/*.md ~/.claude/private/archive/
```

## 2. Новые файлы

```bash
T=~/.claude/claude-config/home/personal/templates
cp $T/people.md $T/projects.md $T/integrations.md ~/.claude/private/
```

Файл фирмы — переписать по новому `templates/firm.md`; клиент — свой файл `firms/<клиент>.md`.

## 3. Было → стало

| Было | Стало |
|---|---|
| `FIRM.TEAM.N` — люди | `PPL` (`people.md`), строка на человека; я — строка `me` |
| `FIRM.<КЛИЕНТ>.1` — проекты и репозитории | `PRJ` (`projects.md`) → «Проекты», «Репозитории» |
| `FIRM.OWN.1`, `FIRM.<КЛИЕНТ>.2` — системы | `INTG` (`integrations.md`), строка на систему; репозиторий, доска, пространство wiki — отдельными строками |
| адреса стендов, тестовый вход | `PRJ` → «Окружения» |
| раздел клиента `FIRM.<КЛИЕНТ>` в файле своей фирмы | свой файл `firms/<клиент>.md` |
| правила фирмы в «Подробно» (часы, почта, обучение, сеть) | `firms/<фирма>.md`, разделы текстом под шапкой |
| `FIRM.OWN.2` — события фирмы | `firms/<фирма>.md` → «События» |
| `PROJ.TEAM` проекта — список людей | `PRJ` → «Люди»; в `PROJ.TEAM` — только чего там нет |
| история, «почему», старые способы доступа | только в `archive/` |
| рецепты (готовые команды) | `INTEG` / `PROJ.CMD` проекта |

Связь пишется в одном месте: кто на проекте и чей проект — только в `PRJ`. В «Когда, кто» — дата последнего факта
из старого текста и чьё слово (`me` — «со слов пользователя»).

## 4. Профиль

Вместо одной строки фирмы — все файлы, через пустую строку:

```text
@~/.claude/private/firms/<своя фирма>.md

@~/.claude/private/firms/<клиент>.md

@~/.claude/private/people.md

@~/.claude/private/projects.md

@~/.claude/private/integrations.md
```

В профиле: доступы (`USER.ACC`) → ссылка на `INTG`; клиенты и проекты (`USER.ABOUT.3`) → `PRJ`.

## 5. Старые ссылки

Номеров `FIRM.TEAM.N`, `FIRM.OWN.N`, `FIRM.<КЛИЕНТ>.N` больше нет. Ссылка — код документа и ID:

| Было | Стало |
|---|---|
| `FIRM.TEAM.3` | `PPL:anna` |
| `FIRM.<КЛИЕНТ>.1` | `PRJ:shop` |
| `FIRM.OWN.1` (трекер) | `INTG:acme-jira-board` |
| `FIRM.OWN.1`, «Учёт часов» | `FIRM:acme` → «Учёт часов» |

Найти:

```bash
grep -rnE 'FIRM\.[A-Z]+\.[0-9]+' ~/.claude/private <repo>/CLAUDE.md <repo>/.claude \
  --exclude-dir=archive --exclude-dir=tickets
```

Документы задач, логи и старые инструкции переезда не трогать — это история.

## 6. Проверка

```bash
grep -n '^@~' ~/.claude/user.md                              # все пять строк
ls ~/.claude/private/people.md ~/.claude/private/projects.md ~/.claude/private/integrations.md
```

Новая сессия Claude Code → спросить «через что ходим в git <репозиторий>?» — ответ из `INTG`, значит подхватилось.
