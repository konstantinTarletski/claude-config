# Переезд проекта с claude-config v1 на v2

Временный файл (удалим, когда все проекты переедут). Читать при переезде (`RULES.MIGR.2`), не грузится всегда.
Образец переехавшего проекта — `resource-be` (14.10.2026). Проверено на пяти проектах: пара `resource-be` +
`resource-fe` (общее — в бэке) и группа `dire` + `dire-ui` + `liiklusregister` (общее — в `dire`, в том числе доступы,
логи и общая БД соседней системы: `INTEG.ALL.101`, `INTEG.LOGS`, `.claude/tech/sql.md`).

**Текущая версия новее 2.0** (первая строка `~/.claude/CLAUDE.md`) — после этого файла сразу следующий:
`v2.0-to-v2.1.md`; метку `2.0` не ставить — в конце одна, текущая.

## 1. Это v1?

Признаки (любой):
- в `<repo>/CLAUDE.md` нет первой строки `<!-- claude-config: 2.0 -->`;
- есть `<repo>/.claude/tasks.md` или `<repo>/.claude/gotchas.md`;
- раздел «Задачи (параметры для `/ticket`)» в `CLAUDE.md`;
- ссылки на `~/.claude/personal/gotchas/…`, `…/code-rules/…`, `…/rules/workflow.md|structure.md|communication.md|safety.md`,
  `…/environment.md`.

Командный `CLAUDE.md`, лежащий в git проекта (`git ls-files CLAUDE.md` не пуст), — **не трогать** (`RULES.PROJ.7`).

## 2. Перед переездом

1. Сказать пользователю одной строкой и ждать «да» (`RULES.MIGR.1`).
2. **Архив** (файлы скрыты от git — вернуть будет неоткуда):
   `tar czf ~/claude-backup/<дата>-<repo>.tgz -C <родитель> <repo>/CLAUDE.md <repo>/.claude`.
3. Связанные проекты (бэк + фронт с общим `tasks.md` через `@../…`) — переводить **подряд**, первым — тот, где лежит
   общий файл: пока второй не переехал, его `@`-ссылки ведут в пустоту.

## 4. Шаги

1. Новый `CLAUDE.md`: первая строка `<!-- claude-config: 2.0 -->` (или текущая — см. начало файла), разделы `PROJ.*`, внизу — `@.claude/work.md`,
   `@.claude/integ.md`, `@.claude/review.md`, `@.claude/tech/<тех>.md` (фронт, у которого общие файлы в бэке, —
   `@../<бэк>/.claude/integ.md` и т. п.). Большие разделы («Архитектура», «Команды») переносить **дословно, скриптом**
   (срез строк), меняя только заголовки и ссылки — так ничего не теряется.
2. `.claude/work.md`, `.claude/integ.md`, `.claude/tech/*.md`, `.claude/tools/` — по таблице. Каждое правило —
   `- **КОД.РАЗДЕЛ.N** (дополняет|заменяет)?` или своё от 101 (`RULES.PROJ.3–4`).
3. Ссылки на старые пути заменить номерами: `~/.claude/personal/gotchas/java-gradle.md → «Jackson 3…»` →
   `JAVA.TRAP.1`; `rules/workflow.md → «Дисциплина изменений»` → `WORK.DISC.7`; `.claude/tasks.md → «…»` → номер.
4. Удалить `tasks.md`, `gotchas.md` — **отдельными командами** (`SAFE.DESTR.1`), после сверки (шаг 5).
5. Новые проектные утилиты — проверить на живом (запустить).

## 5. Проверка, что ничего не потерялось

1. Каждый раздел (`##`/`###`) старых `CLAUDE.md`, `tasks.md`, `gotchas.md` — найти, куда переехал; не нашёл — вернуть.
   Выпало сознательно (дубль общего, устарело) — назвать пользователю.
2. Старых путей нет:
   `grep -rn "personal/gotchas\|code-rules\|rules/\(workflow\|structure\|communication\|safety\)\|environment.md\|tasks.md\|gotchas.md" <repo>/CLAUDE.md <repo>/.claude --include=*.md --exclude-dir=tickets`
   — пусто (документы задач — история, их не правим).
3. Все ссылки-номера существуют: `grep -o "[A-Z]\{2,5\}\.[A-Z]\{3,5\}\.[0-9]\+"` по проекту — каждый номер есть в
   `~/.claude/personal` или в проекте.
4. Всё новое скрыто от git: `git check-ignore -v <repo>/CLAUDE.md <repo>/.claude/work.md`.
5. Метка версии стоит.
6. Пользователю — одной таблицей: что куда переехало, что выпало и почему.
