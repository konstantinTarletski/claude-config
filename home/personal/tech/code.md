# CODE — общее для любого кода

Проверить до отдачи на коммит — `/review-lessons`. Технология — свой файл в `tech/`.

- **CODE.RULE.1** Логика для сущности из внутренней библиотеки (`core`/`common`) → там же, где у соседних сущностей
  (аналог в библиотеке → новый тоже туда, не в приложение). Делать как у аналога один в один: та же сигнатура (типы —
  из библиотеки, не классы приложения), те же проверки входа, то же место; перед сдачей — сравнить построчно. Нет
  доступа к библиотеке → сказать заранее.
- **CODE.RULE.2** Неочевидная строка (явный маппинг, лишняя аннотация, защитная проверка) → доказать экспериментом
  (убрать → собрать → посмотреть) или убрать; «на всякий случай» ревьюеру не ответ. Осталось → «Неочевидное в коде»
  (`/ticket`, шаг 4).
- **CODE.RULE.3** Выбор API без стандарта в проекте (`nanoTime` vs `currentTimeMillis`) → готовый ответ: где в проекте
  так же + ссылка на документацию.
- **CODE.RULE.4** Импорты → только поимённые, без `*` (в том числе статические и в TS: не `import * as x`).
- **CODE.RULE.5** Сгенерированный код → руками не править (перезапишется); мешает → сказать: чинится шаблонами
  генератора или форматтером.
- **CODE.RULE.6** Перед новым кодом → посмотреть 2–3 похожих места в проекте и делать так же. Там плохо (баг,
  устарело) или способы расходятся → не повторять и не «улучшать» молча, сказать.
- **CODE.RULE.7** Язык комментариев, имён, логов → как в соседнем коде, нет образца → английский; мой язык — никогда,
  только по прямой просьбе.

**CODE.LOG** — журнал замечаний ревью (без имён и проектов; проектное — в `<repo>/.claude/review.md`):

- **CODE.LOG.1** Фильтр для сущности из библиотеки сделан в приложении → «должно быть в библиотеке» (`CODE.RULE.1`).
- **CODE.LOG.2** Метод с типами приложения и без проверки входа, а рядом образец в библиотеке → «посмотри, как там»
  (`CODE.RULE.1`).
- **CODE.LOG.3** Явный `@Mapping` для поля, которое MapStruct маппит сам → «зачем» (`JAVA.RULE.1`).
- **CODE.LOG.4** `@Mapping` из-за регистра (`Timezone`/`TimeZone`) → «назови в OpenAPI так же» (`JAVA.RULE.2`).
- **CODE.LOG.5** `System.nanoTime()` → «зачем наносекунды» — ответ: монотонность, а не точность (`CODE.RULE.3`).
- **CODE.LOG.6** Образец X сам отличается от остальных → тестировщик вернул «как у всех»: образец-исключение —
  равняться на большинство, при сомнении спросить аналитика.
- **CODE.LOG.7** Общий метод мапперов — бином через `uses` → «interface + default-метод» (`JAVA.RULE.3`). Третья ошибка
  с MapStruct → перед правкой маппера смотреть соседние.
