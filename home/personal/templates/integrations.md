# INTG — интеграции проектов

Шаблон (`RULES.USER.2`). Копия — `~/.claude/private/integrations.md` (**вне репозитория**), подключается `@`-ссылкой из
профиля. **Источник правды:** куда ходим и через что — только здесь, остальные ссылаются по ID (из правил —
`INTG:<id>`). **Только текущее состояние:** поменялся способ — правим «Через что», старый строкой не оставляем.
Вести сразу: появилось → строка; перестало работать (401, истёк токен, пропал VPN) → «Живая: нет — почему», а не
обходить молча.
Секретов нет: токены — только имена (`INTEG.ALL.2`), значения — в `~/.bashrc`.

| ID | Проект | Что | Через что | Живая | Когда, кто | Адрес |
|---|---|---|---|---|---|---|
| `<фирма>-jira-board` | `<проект>`, `<проект>` | Jira <фирма>, доска «<название>» | MCP «<коннектор>» | да | <ДД.ММ.ГГГГ>, `me` | https://… |
| `git-<проект>-<часть>` | `<проект>` | git, <бэк / фронт / e2e> | SSH-ключ `<ключ>`; API — токен `<ФИРМА>_<СИСТЕМА>_TOKEN` | да | <ДД.ММ.ГГГГ>, `me` | https://… |
| `<клиент>-jira-<проект>` | `<проект>` | Jira клиента | браузер | да | <ДД.ММ.ГГГГ>, `me` | https://… |
| `<фирма>-mail` | `<фирма>` | почта, календарь | — | нет — <почему: нельзя, ждём доступ, …> | <ДД.ММ.ГГГГ>, <`me`, `<id>`> | — |

- **ID** — общая система фирмы: `<фирма>-<система>`; система одного проекта: `<система>-<проект>-<часть>`.
- **Проект** — ID из `PRJ`; система всей фирмы — ID фирмы из `FIRM`.
- **Живая** — `да` или `нет — <почему>`.
- **Когда, кто** — дата последнего решения и кто решил (`me`, ID из `PPL`).
- **Адрес** — полный, с `https://`; git — каждый репозиторий отдельно; трекер — доска и проекты клиента отдельно.
