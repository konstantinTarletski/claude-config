# Структура файлов: что где лежит и что куда писать

Всё, что я прошу запомнить, записывать **сразу в файл**, а не держать в голове до конца сессии.
Место выбирать по таблице ниже.

**Напоминать про коммит в `claude-config`.** Изменил что-то в моих личных настройках (всё под
`~/.claude/personal`, `~/.claude/CLAUDE.md`, т.е. в `/mnt/c/code/claude-config`) — в конце ответа
проверить `git -C /mnt/c/code/claude-config status --short` и неотправленные коммиты
(`git -C /mnt/c/code/claude-config log --oneline @{u}..`; «no upstream» — ветка ещё ни разу не
отправлена, нужен `git push -u origin main`) и, если что-то есть, отдельной строкой
написать: какие файлы не закоммичены / сколько коммитов не отправлено и команду
(`cd /mnt/c/code/claude-config && git add -A && git commit -m "..." && git push`). Коммитит и
пушит пользователь сам.

**Нашёл сам — записывай сразу, не спрашивая.** Грабля, костыль, находка по тикету, правило общения
или работы, уточнение существующего правила — если по этой карте ему есть место, записать сразу и
в ответе одной строкой сказать, что и куда записано. Не предлагать «Записать?» — я поправлю или
откачу, если не согласен. Спрашивать только когда непонятно, куда писать, или запись меняет смысл
уже принятого правила.

**Где файлы лежат физически.** Мои личные настройки (`~/.claude/CLAUDE.md`, `~/.claude/personal/`) —
в git-репозитории `/mnt/c/code/claude-config` (`C:\CODE\claude-config`), в `~/.claude` — симлинки
туда (`install.sh`); новый скилл — в `claude-config/home/personal/skills/<имя>` + `./install.sh`.
Всё проектное (`CLAUDE.md`, `.claude/gotchas.md`, `.claude/tickets/`, `.sdkmanrc`/`.nvmrc`) — обычными
файлами **в самом проекте**, в `claude-config` не переносить. Свои файлы в проекте скрывать через
`<repo>/.git/info/exclude`, а не `.gitignore` проекта (его не трогать).

## Карта

```
~/.claude/
├── CLAUDE.md                     # только @-импорты personal/*.md — грузится во всех проектах
├── personal/                     # ПЕРЕНОСИМОЕ: без специфики компании/проекта
│   ├── README.md                 # что здесь и как перенести
│   ├── structure.md              # этот файл — карта
│   ├── gotchas.md                # общие грабли — не про конкретный проект
│   ├── communication.md          # общение со мной
│   ├── environment.md            # Java/Node — свои из WSL (sdkman, nvm)
│   ├── skills/<имя>/SKILL.md     # общие скиллы (estimate, ticket); симлинк в ~/.claude/skills/
│   ├── templates/ticket.md       # шаблон документа по задаче
│   └── workflow.md               # как работаем над задачами
└── projects/<проект>/memory/     # память ассистента по проекту (личный контекст)

<repo>/                            # всё ниже — в .gitignore, локальное
├── CLAUDE.md                     # правила и устройство ЭТОГО проекта; @-импортирует gotchas.md
└── .claude/
    ├── gotchas.md                # грабли и костыли проекта
    ├── skills/<имя>/SKILL.md     # повторяющийся порядок действий в проекте
    └── tickets/                  # документы по задачам — содержимое проекта
        ├── <KEY>.md              # ход работы по тикету
        └── <YYYY-MM-DD>-<тема>.md  # ход работы по теме без тикета
```

## Что куда

| Что | Куда |
|---|---|
| Общее правило для всех проектов (как общаться, оценивать, работать) | `~/.claude/personal/<тема>.md` |
| Правило или устройство конкретного проекта (архитектура, команды, домен) | `<repo>/CLAUDE.md` |
| **Грабли и костыли проекта**: как правильно запускать тесты, почему что-то сделано «через одно место», обходной путь для неочевидной ошибки — найденное мной или подсказанное пользователем | `<repo>/.claude/gotchas.md` |
| **Общие грабли** — не про проект, а про инструмент, ОС, библиотеку (встретится и в другом проекте) | `~/.claude/personal/gotchas.md` |
| Повторяющийся порядок действий, общий для всех проектов (оценка и т.п.) | `~/.claude/personal/skills/<имя>/SKILL.md` + симлинк `~/.claude/skills/<имя>` |
| Повторяющийся порядок действий в проекте | `<repo>/.claude/skills/<имя>/SKILL.md` |
| Ход работы по тикету (содержимое — про проект) | `<repo>/.claude/tickets/<KEY>.md`, копия `~/.claude/personal/templates/ticket.md` |
| Как работать с тикетами (порядок, шаблон) — мои настройки | скилл `~/.claude/personal/skills/ticket`, шаблон `templates/ticket.md`; проектные параметры — раздел «Задачи» в `<repo>/CLAUDE.md` |
| Ход работы по теме без тикета | `<repo>/.claude/tickets/<YYYY-MM-DD>-<тема>.md` |
| Личный контекст о пользователе и его планах | память ассистента |

Как отличить `CLAUDE.md` от `gotchas.md`: «как устроено» → `CLAUDE.md`; «почему не работает
очевидным способом и как обойти» → `gotchas.md`. Запись в `gotchas.md`: **симптом → причина
(`файл:строка`) → как правильно**.

**Какой `<repo>`.** Запись идёт в проект, **к которому относится** — где менялся код или где живёт грабля, а
не где открыта сессия: про бэкенд — в бэкенд, про фронт — во фронт. Касается связанных проектов обоих (бэк и
его фронт: общий трекер, токены, сеть, git-сервер) — записать в тот, куда подходит лучше, а в соседнем
поставить пометку-ссылку «см. `../<другой>/…`» (в `gotchas.md` / `CLAUDE.md` соседнего). Документ по задаче,
если код менялся в обоих, — в обоих (см. `workflow.md`).

Грабли по умолчанию — **свои у каждого проекта**. В общий `personal/gotchas.md` — только то, что
точно повторится в другом проекте; формулировать без путей и имён компании.

Грабля, найденная по ходу тикета, сначала пишется в документ тикета («Грабли»), а если она про
проект вообще — переносится в `gotchas.md`.

## Правила

- **Переносимость.** В `personal/` — ничего специфичного для компании: ни адресов, ни ключей
  задач, ни кода проекта. Всё это — в `<repo>/`.
- **Не дублировать.** Одно правило — одно место. Проектный файл может сослаться на общий, но не
  копировать его.
- **Разделять по смыслу, но не дробить.** Новый файл — только под новую тему, иначе дописывать в
  существующий.
- **Всё моё в репозитории — скрыто от git.** Заводишь новое место в `<repo>/` — сразу проверить
  (`git check-ignore -v <путь>`) и при необходимости добавить в `<repo>/.git/info/exclude`
  (локально, не коммитится; `.gitignore` проекта не трогать).
- Командные файлы, лежащие в git (например, общие заметки команды), — не наши: свои находки
  туда не дописывать.
- **Правило или скилл?** Нужно в каждой сессии (как общаться, что куда писать) — файл, `@`-импорт
  из `CLAUDE.md`. Пошаговая процедура, нужная по запросу (оценка, ведение тикета) — скилл: в
  контексте только его `description`, тело грузится при вызове.
- `CLAUDE.md` подгружается сам; всё остальное, что нужно в каждой сессии, подключать через
  `@путь` из соответствующего `CLAUDE.md`.
