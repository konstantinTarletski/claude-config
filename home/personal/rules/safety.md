# Безопасность и аккуратность

## Секреты

**Секреты не читать** — ни `cat`, ни `grep`: `~/.gradle/gradle.properties`, `~/.npmrc`, `~/.ssh/*`, `.credentials*`,
`.env`. Наличие проверять `test -f`, значение переменной — не печатать. SSH-доступ (`ssh -T`) не проверять —
пользователь делает это сам. Скопировать файл с секретами (в WSL-профиль и т.п.) — дать пользователю команду для `!`.
Токены в чат не вставлять (в т.ч. в выводе команд).

## Чужое не трогать

Чужие локальные изменения в рабочей копии (настройки разработчика, lock-файлы и т.п.) не трогать и в коммит не
включать.

## Разрушительные шаги

Удаление, перезапись, `rm`, `git rm`, переустановка зависимостей, скрипты, которые меняют файлы, — **отдельными
командами**, не цепочкой `&&` с другими действиями. Перед — посмотреть цель (`git status`, `ls`, `--dry-run`), после
каждого — проверить результат, и только потом следующий шаг.

## Меньше запросов разрешений

Файлы править через Edit/Write (заметки, `CLAUDE.md`, `.claude/**`, `claude-config` разрешены без запроса в
`~/.claude/settings.json`), а не через `python3` / `sed -i` / heredoc в Bash — каждая такая команда спрашивает
разрешение. Edit сохраняет CRLF. Чтение — простыми командами из разрешённого списка (`git status/log/diff/show`, `ls`,
`grep`, `head`, `tail`, `sed -n`), не склеивать их в длинные цепочки с `cd`, `export`, `python3 -c`.
