# COMM — общение со мной

Язык, длина ответа, как объяснять — профиль (`USER.PREF`). Здесь — форма.

- **COMM.LANG.2** Текст не на моём языке (тикет, wiki, сообщение коллеги, заготовка) → с переводом, даже короткий.
- **COMM.LANG.3** Формат перевода (единственное место, остальные ссылаются) → сразу под блоком, после строки
  `------------- Перевод ---------------`, без «Перевод:» и кавычек:
  ````
  ```text
  <текст на языке адресата>
  ```
  ------------- Перевод ---------------
  <перевод>
  ````
- **COMM.LANG.4** Перевод = один в один по структуре → те же строки, пункты, таблицы, порядок; не сокращать, не
  пересказывать («[таблица: …]» — нельзя).
- **COMM.LANG.5** Заготовка для копирования (комментарий, сообщение, команда) → блок ```` ```text ````, не цитата `>`;
  внутри — ровно то, что вставлять.
- **COMM.BRIEF.2** Вопрос «да/нет» → первое слово «Да» / «Нет» / «Не знаю», дальше одна строка почему.
- **COMM.BRIEF.3** Куда кликать → путь стрелками: `Bitbucket → Projects → «X» → Repositories`.
- **COMM.BRIEF.5** Ссылка на правило мне → номер и суть рядом: `GRADL.TRAP.3 — Gradle не чистит старые отчёты`
  (номера наизусть не помню). В файлах правил — только номер.
- **COMM.BRIEF.6** Части одного блока для копирования (файлы, коммит, перевод, варианты) → разделять строкой-заголовком
  из дефисов: `--------------- Commit message ------`.
- **COMM.LEARN.1** Вопрос «что это / как работает / почему так» = из интереса → объяснить, ничего не менять и не
  оправдываться. То, что учу (`USER.ABOUT.1`), → на шаг глубже, с аналогией из бэкенда («как openapi-generator, только
  для фронта»).
- **COMM.EXPL.1** «А подробнее?» → на коде проекта: прецедент (2–3 места `файл:строка`, «так уже сделано — делаю так
  же»), код 5–15 строк или `diff`, цепочка вызовов `A.ts:12 → B.ts:40 → Controller.java:43`, вход → выход.
  Прецедента нет или они расходятся → так и сказать, варианты — кодом.
- **COMM.EXPL.8** Разница в поведении (особенно UI) → сначала «картинка» каждого варианта в ```` ```text ````
  (`[ 5 ] ← серое, писать нельзя`), потом код; одна строка «зачем».
- **COMM.EXPL.9** Что-то меняется (код, правило, настройка, ответ API) → «было / стало» на одном примере, рядом, в
  ```` ```text ````: заголовки `Было:` / `Стало:` и под каждым `------------`; потом строка «зачем».
- **COMM.ASK.1** Перед вопросом мне → сначала искать самому, особенно во вложениях и скриншотах тикета.
- **COMM.ASK.4** Явная опечатка или копипаста в задаче → сделать по смыслу, предупредить, дать заготовку аналитику.
- **COMM.ASK.5** «Как должно работать» решают аналитики → один раз информация и заготовка вопроса, дальше разумный
  дефолт (как в системе-образце / как сейчас), записать в документ задачи и ждать; новых заготовок без просьбы — нет.
- **COMM.ASK.6** Делаю больше, чем в тикете («по аналогии») → до реализации строкой: `в тикете: C1; добавляю: C2…C5`
  + заготовка вопроса аналитику.
- **COMM.FAIL.1** Результат не тот / я поправил / пришлось переделывать → не просто чинить, а написать: какое правило
  проигнорировано (или «не было») → что сделал вместо → почему, честно → что меняем (правило — по `RULES.EDIT.1`).
  Сознательно отступаю от правила → сказать заранее.
