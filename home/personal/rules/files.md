# FILES — что куда писать

Ведение самих правил (номера, размеры, правка) — `RULES` и скилл `/rules`. Здесь — куда писать найденное по ходу.

- **FILES.NOW.1** Попросили запомнить или нашёл сам (грабля, находка по тикету, замечание ревью) → сразу в файл, не
  спрашивая «записать?»; в ответе одной строкой — полный путь и номер: `shop-be/.claude/tech/sql.md` → `SQL.TRAP.104`.
  Новый факт обо мне или окружении → сразу в профиль (`RULES.USER.1`). Правила (не грабли) → только после «меняй».
- **FILES.WHERE.1** Что → куда:

  | Что | Куда |
  |---|---|
  | обо мне и окружении: кто я, настройки, разрешения, система, инструменты, доступы, папки | профиль `USER` (`~/.claude/user.md`, не в git) |
  | фирма и клиенты: проекты, репозитории, системы, адреса, имена токенов | `FIRM` (`private/firms/<фирма>.md`, не в git) |
  | общение, задача, безопасность, что куда, внешние системы | `personal/rules/` — `COMM`, `WORK`, `SAFE`, `FILES`, `INTEG` |
  | технология: установка, как писать, грабли | `personal/tech/<тех>.md` — `SETUP`, `RULE`, `TRAP` |
  | общее для любого кода + журнал замечаний ревью | `personal/tech/code.md` — `CODE.RULE`, `CODE.LOG` |
  | процедура по вызову | `personal/skills/<имя>/SKILL.md` |
  | общая утилита | `personal/tools/` |
  | проект: о проекте, команды, архитектура, люди, события | `<repo>/CLAUDE.md` — `PROJ` |
  | проект: отличия от общих правил | `<repo>/.claude/<код>.md`, `<repo>/.claude/tech/<тех>.md` — те же номера |
  | проект: замечания ревью | `<repo>/.claude/review.md` (`WORK.REVW.1`) |
  | проект: утилиты, свой запуск (compose, скрипты, `.env`) | `<repo>/.claude/tools/`, `<repo>/local-env/` |
  | документы по задаче | `<repo>/.claude/tickets/` (`FILES.DOCS.1`) |
  | контекст разговора — не факт и не правило («на потом») | память ассистента |
  | разрешения, тема, строка состояния | `settings.json` — не правила |

- **FILES.WHERE.2** Какой `<repo>` → тот, к которому относится (где менялся код, где живёт грабля), а не где открыта
  сессия. Касается бэка и фронта сразу → в более подходящий, в соседнем — ссылка `../<другой>/…`.
- **FILES.WHERE.4** Тема без тикета (исследование, окружение) → документ `<repo>/.claude/tickets/<дата>-<тема>.md`; тема
  не про репозиторий (настройки ассистента) → документа не нужно, итог — в самих правилах.
- **FILES.WHERE.5** Грабля → записывать, только если ценная: сложно найти (ушло много времени), повторяется часто,
  обход или костыль в проекте. Мелочь, которую видно по первой же ошибке, → не записывать.
  Про технологию → общий `personal/tech/<тех>.md` → `TRAP`, общими словами, без имён проекта, с меткой версии
  (`RULES.VER`); в проекте — только его конкретика и ссылка. Целиком про устройство проекта → `<repo>/.claude/tech/`.
- **FILES.WHERE.6** Как отличить: «как устроено» → `PROJ`; «не работает / не запускается» → `TRAP` (симптом →
  причина → как правильно); «работает, но ревьюер спросит зачем» → `RULE` (правило → почему → как проверить).
- **FILES.WHERE.7** Командные файлы в git проекта (общие заметки команды) → не наши, свои находки туда не дописывать.
- **FILES.WHERE.8** Всё моё в репозитории → скрыть через `<repo>/.git/info/exclude`, не `.gitignore`; проверить —
  `git check-ignore -v <путь>`.
- **FILES.WHERE.9** В проекте → только значения (адреса, команды, задачи); структура файлов `.claude/`, разделы, общие
  команды → из personal (`personal/templates/`). Одинаковое для всех клиентов → в personal (скилл, утилита).
- **FILES.DOCS.1** Документы задачи → `<repo>/.claude/tickets/` без подпапок:
  `<KEY>.md` — ход работы (шаблон `personal/templates/ticket.md`), дописывать сразу;
  `<KEY>.in.<исходное имя>` — пришло извне (логи, скриншоты, вложения), имя не менять;
  `<KEY>.out.<для-кого>-<язык>.<расш>` — сделано для других (`SA-2176.out.analyst-et.md`), рядом `-ru`.
- **FILES.DOCS.4** Наружу (wiki, трекер, письмо) → только из `.out.` и после «да».
- **FILES.TOOLS.1** Утилита → только если повторяется и запускать быстрее, чем писать заново. Под один проект →
  `<repo>/.claude/tools/`; пригодится где угодно → `personal/tools/` (адреса и токены — параметрами, ничего про фирму).
