# FILES — что куда писать

Ведение самих правил (номера, проект, размеры, правка) — `RULES` в `~/.claude/CLAUDE.md`. Здесь — куда писать то, что
находится и создаётся по ходу работы.

## FILES.NOW — записывать сразу

- **FILES.NOW.1** Всё, что я прошу запомнить, — **сразу в файл**, а не держать в голове до конца сессии. Нашёл сам
  (грабля, костыль, находка по тикету, замечание ревью) — записать сразу, не спрашивая «Записать?», и в ответе одной
  строкой сказать, что и куда — **полным путём**, с репозиторием: `shop-be/.claude/tech/sql.md` → `SQL.TRAP.104`,
  `claude-config/home/personal/rules/files.md` → `FILES.NOW.1` (не «записал в sql.md» / «в правила»). Спрашивать,
  только если непонятно, куда писать, или запись меняет смысл принятого правила. Правила (не грабли и не документы) —
  по `RULES.EDIT.1`. Новый факт обо мне или окружении (версия, настройка, доступ, папка, событие) — сразу в профиль
  `USER` (`RULES.USER.1`).

## FILES.WHERE — что куда

- **FILES.WHERE.1** Таблица:

  | Что | Куда |
  |---|---|
  | Ведение правил: номера, проект, версии, размеры, правка | `~/.claude/CLAUDE.md` → `RULES` |
  | **Обо мне и окружении**: кто я, настройки, разрешения, система, инструменты, доступы машины, папки, мои события | `~/.claude/user.md` → `personal/users/<имя>_<фирма>.md` — `USER` (не в git) |
  | **Фирма и клиенты**: проекты (синонимы), репозитории, системы — есть ли, адрес, имя токена | `personal/firms/<фирма>.md` — `FIRM` (не в git, `RULES.USER.2`) |
  | Общение со мной | `personal/rules/comm.md` — `COMM` |
  | Работа над задачей: порядок, дисциплина, проверка, сдача, оценка | `personal/rules/work.md` — `WORK` |
  | Секреты, чужое, разрушительные шаги, разрешения | `personal/rules/safe.md` — `SAFE` |
  | Куда что писать (этот файл) | `personal/rules/files.md` — `FILES` |
  | Внешние системы: токены, трекер, wiki, git-сервер, почта, чат | `personal/rules/integ.md` — `INTEG` |
  | **Технология**: установка (`SETUP`), как писать (`RULE`), грабли (`TRAP`) | `personal/tech/<тех>.md` |
  | Общее для любого кода + журнал замечаний ревью | `personal/tech/code.md` — `CODE.RULE`, `CODE.LOG` |
  | Готовые утилиты (Jira, wiki, отчёты тестов) | `personal/tools/` (`FILES.TOOLS`) |
  | Процедура по вызову | `personal/skills/<имя>/SKILL.md` + `./install.sh` |
  | Проект: о проекте, команды, архитектура, люди, события (стендап, демо) | `<repo>/CLAUDE.md` — `PROJ` |
  | Проект: отличия от общих правил, конкретика | `<repo>/.claude/<код>.md`, `<repo>/.claude/tech/<тех>.md` — те же номера |
  | Проект: замечания ревью | `<repo>/.claude/review.md` (`WORK.REVW`) |
  | Проект: настройки отдельного скилла | `<repo>/.claude/<скилл>.md` (`timelog-askend.md`) — **без** `@`, читает только скилл |
  | Проект: утилиты | `<repo>/.claude/tools/` |
  | Проект: процедура по вызову | `<repo>/.claude/skills/<имя>/SKILL.md` |
  | Документы по задаче | `<repo>/.claude/tickets/` (`FILES.DOCS`) |
  | Контекст разговора, который не факт и не правило (о чём договорились «на потом», ход обсуждения) | память ассистента — со ссылкой на `USER` / `PROJ`, без дублей |
  | `settings.json` (`~/.claude/` → `personal/users/<имя>_<фирма>.settings.json`, не в git), `settings.local.json` | разрешения команд, тема, строка состояния — не правила, не нумеруются |

- **FILES.WHERE.2** **Какой `<repo>`.** Запись идёт в проект, **к которому относится** — где менялся код или где живёт
  грабля, а не где открыта сессия. Касается связанных проектов обоих (бэк и его фронт: общий трекер, токены, сеть,
  git-сервер) — в тот, куда подходит лучше, в соседнем — ссылка «см. `../<другой>/…`».
- **FILES.WHERE.3** **Документ по задаче** — в репозитории, **где меняется код задачи** (фронтовая задача → во фронте,
  даже если сессия открыта в бэке). Код в нескольких репозиториях — документ **в каждом**: суть и общие решения в
  обоих (или в одном, а во втором — ссылка), «что сделано» / «как проверить» / коммиты — про этот репозиторий; в
  «Связях» (`FILES.DOCS.5`) — ссылка на соседний. Мелкий вопрос в рамках текущего тикета — не новая тема: в документ
  тикета.
- **FILES.WHERE.4** **Тема без тикета** (исследование, окружение, договорённости) — такой же документ, ключ — дата и тема
  (`2026-09-25-claude-settings.md`). Тема не про конкретный репозиторий (общие настройки ассистента) — документа не
  нужно, итог — в самих правилах.
- **FILES.WHERE.5** **Грабля про технологию — в `personal/tech/<тех>.md` → `TRAP`**, даже если нашлась в конкретном
  проекте: общими словами, без путей, имён компании, классов и id проекта («Jackson 3 не видит `@JsonProperty` на
  унаследованных полях», а не «`jsonMapper` в `BaseIntegrationTest`»), с меткой версии (`RULES.VER`). В проекте —
  только его конкретика под своим номером и ссылка на общий. Грабля целиком про устройство проекта — только в
  `<repo>/.claude/tech/<тех>.md`. Грабля по ходу тикета — сначала в документ тикета, про проект вообще — в `tech/`
  проекта.
- **FILES.WHERE.6** Как отличить: «как устроено» → `PROJ` в `CLAUDE.md` проекта; сломалось, не компилируется, не
  запускается, «почему не работает очевидным способом» → `TRAP` (симптом → причина → как правильно); работает, но
  ревьюер спросит «зачем так» → `RULE` (правило → почему → как проверить).
- **FILES.WHERE.7** Командные файлы, лежащие в git (общие заметки команды), — не наши: свои находки туда не дописывать.
- **FILES.WHERE.8** **Всё моё в репозитории — скрыто от git**: новое место в `<repo>/` — проверить
  (`git check-ignore -v <путь>`) и при необходимости добавить в `<repo>/.git/info/exclude`, а не в `.gitignore` проекта.
- **FILES.WHERE.9** **Какие файлы и с какой структурой заводить в `<repo>/.claude/` — только из personal**
  (`FILES.WHERE.1`, шаблоны `personal/templates/`). В проекте — **только значения** (адреса, задачи, токены, команды
  проекта), без своих разделов, путей к моим папкам (`USER.FOLD`) и общих команд: одинаковое для всех клиентов — в
  personal (скилл, утилита); в проекте — только то, что у этого клиента иначе (версия, флаги).

## FILES.DOCS — документы по задаче

- **FILES.DOCS.1** Всё по задаче — в `<repo>/.claude/tickets/`, **без подпапок**: `<KEY>.md` — ход работы (копия
  `personal/templates/ticket.md`), дописывать сразу, а не в конце по памяти.
- **FILES.DOCS.2** Пришло извне (логи, скриншоты, вложения, выгрузки wiki/jira) — `<KEY>.in.<исходное имя>`; исходное
  имя **не менять**, только приставка.
- **FILES.DOCS.3** Сделано для других (аналитику, для релиза, текст для wiki, письмо) —
  `<KEY>.out.<для-кого>-<язык>.<расширение>` (`SA-2176.out.analyst-et.md`); оригинал и `-ru` — рядом.
- **FILES.DOCS.4** Наружу (wiki, трекер, письмо) — только из `.out.`, после моего «да».
- **FILES.DOCS.5** **Раздел «Связи» в документе задачи — вести всегда и в обе стороны.** В каждом `<KEY>.md` в
  конце — раздел «Связи» на **все** тикеты, к которым он относится: эпик и все его тикеты со статусом на дату, связи из
  трекера, тикеты из кода, коммитов и соседних документов, старые ключи → новые (тикет перенесли в другой проект), где
  лежат документы этих тикетов в других репозиториях (`../<репо>/.claude/tickets/…`). Нашёл связь A → B — сразу
  дописать и обратную B → A в документ B. **У тикета B документа нет — завести** `<KEY>.md` там, где будет его код
  (`FILES.WHERE.3`; неясно — в главном репозитории группы): заголовок, строка «заведён как связанный с `<KEY>`, работа
  не начиналась» и раздел «Связи». Обновлять при каждом заходе в тикет — статусы меняются.

## FILES.TOOLS — утилиты

- **FILES.TOOLS.1** Утилита — только если она **повторяется и запуск быстрее**, чем написать заново.
- **FILES.TOOLS.2** **Утилита под конкретный проект — остаётся в проекте** (`<repo>/.claude/tools/`). В
  `personal/tools/` — только то, что **пригодится где-то ещё** (любая фирма, любой проект): адреса и токены —
  параметрами/переменными, внутри ничего про фирму и проект.
- **FILES.TOOLS.3** В первых строках файла — что делает и как запускать. Секретов внутри нет: токен из env
  (`INTEG.ALL.1`).
- **FILES.TOOLS.4** Список утилит с одной строкой описания — в `~/.claude/CLAUDE.md` → «Коды файлов и утилиты» и в
  дереве `README.md` `claude-config` (общие) и в `PROJ.TOOLS`
  проекта (проектные, с готовой командой запуска).
