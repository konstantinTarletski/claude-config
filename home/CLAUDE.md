# Общие правила для всех проектов

Все файлы правил подключены внизу и грузятся всегда. Как **вести** правила (номера, размеры, новый файл, проект,
переезд) — скилл `/rules`.

## RULES — как читать правила

- **RULES.CODE.1** Номер = `ФАЙЛ.РАЗДЕЛ.N` (`COMM.LANG.3`) → коды файла и раздела — 3–5 латинских букв; код файла — в
  списке ниже.
- **RULES.CODE.3** В `tech/` разделы одинаковые → `SETUP` установка, `RULE` как писать, `TRAP` грабли (симптом →
  причина → как правильно).
- **RULES.PROJ.1** Что важнее → моё слово в чате → правило проекта (репозитория, где работаем) → общее. Для всех правил,
  включая git и сам `claude-config`. Исключения «для такого-то репозитория» — только в правилах этого репозитория.
- **RULES.PROJ.2** В проекте → те же файлы и номера, что в общих (`<repo>/.claude/work.md` ↔ `rules/work.md`), только
  отличия и конкретика. Тот же номер → дополняет общее; с пометкой `(заменяет)` → заменяет. Свои правила проекта в
  общем разделе → номера от 101.
- **RULES.PROJ.6** Разделы только проекта → `PROJ` в `<repo>/CLAUDE.md`: `ABOUT` о проекте, `CMD` команды, `ARCH`
  архитектура, `TEAM` люди, `TOOLS` утилиты, `EVENT` события (прошедшие разовые — удалять).
- **RULES.PROJ.7** Метка версии → первая строка `<repo>/CLAUDE.md`: `<!-- claude-config: 3.0 -->`. Командный
  `CLAUDE.md` в git проекта → не наш, своё — в `.claude/`.
- **RULES.VER.1** Правило или грабля с меткой версии (`[Spring Boot 3+]`, `[Spring 4.0–4.3]`) → применять, только если
  версия проекта подходит (смотреть до первой правки). Без метки → для всех версий. Второй список — где точно нет:
  `[PostgreSQL 17–18; нет: PostgreSQL 15]`. Версия в «нет» → не применять; ни в одном списке → не применять, а сказать:
  «есть грабля <номер>, на нашей версии не проверена».
- **RULES.OFF.1** Выключенные правила → список в профиле (`USER.OFF`): номер (`COMM.EXPL.9`) или раздел (`WORK.EST` —
  выключены все его правила). Выключено проектное → работает общее с тем же номером.
- **RULES.USER.1** Обо мне и окружении → профиль `USER` (`~/.claude/user.md`): кто я, настройки, разрешения, система,
  инструменты, доступы, папки. Правила такие факты не повторяют — ссылаются на номер. Новый факт → сразу туда.
  Только проверенное: командой, которая показывает именно это, или «со слов пользователя»; не знаешь — не писать.
- **RULES.USER.2** Фирма и клиенты → файл `FIRM` (`private/firms/<фирма>.md`, подключён из профиля): проекты с
  синонимами, репозитории, системы — есть / нет доступа / не проверено, адрес, имя токена. Описание системы — только
  здесь; в `INTEG` проекта — рецепты со ссылкой сюда. Вести сразу, с датой: появилось → дописать; перестало работать
  (401, истёк токен, пропал VPN) → исправить, а не обходить молча. Проект назван синонимом → репозиторий по `FIRM`.
- **RULES.EDIT.1** Правила (`CLAUDE.md`, `rules/`, `RULE` и `SETUP` в `tech/`, правила проекта) → только после «меняй»:
  сначала обсуждаем, я предлагаю текст и номер. Сразу, без «меняй» → документы задач, грабли, замечания ревью,
  калибровка оценок, память.
- **RULES.EDIT.5** Правка файла правил (общего или проектного, в том числе новая грабля) → сначала скилл `/rules`.
- **RULES.MIGR.1** Проект без метки версии или со старой → одной строкой «проект на v<его>, перевести на v<текущая>
  (`/rules`)?» и ждать «да».

## Коды файлов и утилиты

Дерево с размерами — `~/.claude/claude-config/README.md`.

- **Профиль** `USER` — `~/.claude/user.md`; **фирма** `FIRM` — `private/firms/<фирма>.md` (оба не в git, шаблоны —
  `personal/templates/`).
- **`personal/rules/`:** `COMM` общение · `WORK` задача · `SAFE` безопасность · `FILES` что куда · `INTEG` внешние
  системы.
- **`personal/tech/`:** `CODE` · `JAVA` · `GRADL` (gradle.md) · `API` · `NODE` · `NG` · `GIT` · `WSL` · `TLS` · `SQL`.
- **Утилиты `personal/tools/`** (не грузятся): `jira.py` тикет текстом · `wiki.py` страница с пометками изменений ·
  `bb-pr.py` PR Bitbucket · `test-count.sh` тесты в отчётах · `with-token.sh` команда с токеном из `~/.bashrc` ·
  `session-time.py` часы по сессии (`/estimate`) · `flyway-checksum.py` сумма миграции · `jira-worklog.py` часы в Jira
  (`/timelog-askend`).
- **Проект:** `<repo>/CLAUDE.md` (`PROJ`, метка версии) + `<repo>/.claude/` (те же коды, `tickets/`, `tools/`) —
  скрыто через `.git/info/exclude`.
